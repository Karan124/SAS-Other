Answers to clarification questions:

1. File 3 column names are exactly:
   process_category
   process_lifecycle_stage

2. Do not filter by CTRL_STUS at this stage. The payment controls population is already pre-defined as 708 controls. Known status values include "Assessed", but the active status taxonomy has not been confirmed.

3. Yes, Gold Control CT1-CT28 should be a core analysis dimension alongside payment category and lifecycle stage.

4. There are 5 valid payment categories:
   - Customer to Customer
   - Customer to Institution
   - Institution to Customer
   - Institution to Institution
   - Supplier / Contractor / Employee Payments

   Values such as 0 should be treated as Unclassified / Missing.

5. Exact lifecycle stage strings observed:
   - Clearing / Settlement
   - Execution & Early Processing Assurance
   - Incident response, disputes, recovery followups
   - Initiation & Validation & Authorisation
   - Notification & Reporting
   - Posting & Accounting, Detection
   - Posting, Accounting & Detection

   The last two should likely be normalised to:
   Posting & Accounting, Detection

6. File 1 to File 2 join key is:
   juno_payment_controls_gold.Control_ID = juno_holo_deterministic_linkage.CTRL_ID

7. Yes, L2-only rows exist in File 2. Some rows have l2_process_uuid / l2_process_id populated but l3_activity_uuid and l3_activity_id blank. This is critical because L2-only linkages cannot automatically inherit a single payment category or lifecycle stage without expanding to child L3 activities, which risks overstating coverage.
